## Process crash vs power loss, per fsync policy

`kill -9` alone cannot test fsync: the page cache survives a process crash. These suites use `PowerLossJournal`, which keeps un-fsynced records in user space, so a SIGKILL loses exactly what a power failure would lose. `LLM calls re-billed` counts completed runs only (10 calls are needed).

| Suite | fsync | Model | Runs | Kills | Violating runs | Acked records lost | LLM calls re-billed | Billed calls / completed run |
|---|---|---|---|---|---|---|---|---|
| aw-pl-always | always | deterministic | 300 | 396 | 0 | 0 | 51 | 10.17 |
| aw-pl-group | group:8:5 | deterministic | 300 | 404 | 0 | 0 | 43 | 10.14 |
| aw-pl-none | none | deterministic | 300 | 425 | 0 | 0 | 1274 | 14.25 |
| aw-pl-always-stoch | always | sampled | 200 | 276 | 0 | 0 | 38 | 10.19 |
| aw-pl-none-stoch | none | sampled | 200 | 264 | 118 | 0 | 9 | 10.11 |

How to read this: with a deterministic model even `none` stays correct, because the idempotency key is derived from `(run_id, seq)` and the receiver deduplicates; what `none` costs is re-billed LLM calls (the whole journal is lost at each crash). With a sampled model, `none` breaks resume: a lost `LLM_RESULT` is re-sampled, a different amount is sent under the old key, and the receiver rejects it. Errors in `aw-pl-none-stoch`: 118× 409 idempotency key reused with different parameters. No money moved incorrectly (0 duplicated, 0 wrong), but those runs cannot finish without a human. With `always` or group commit, the barrier before each effect makes the decision durable before it is acted on, so the same sampled model has no violations.

## The receiver assumption

An intent without a result is ambiguous: the effect may or may not have happened. AgentWAL either retries with the same idempotency key (safe only if the receiver deduplicates) or asks the receiver `GET /payments?key=` first (reconcile).

## Torn writes

After every kill the journal was truncated at a uniformly random byte offset (422 tears over 300 runs); recovery truncates to the last valid record and replay re-executes the rest with the same idempotency keys. Violating runs: **0**, duplicated effects: 0, lost effects: 0.

Unit and property tests cover the same at the record level (`tests/property/test_props.py`: truncation at any offset recovers exactly a prefix; a single corrupted byte never yields a wrong record).
